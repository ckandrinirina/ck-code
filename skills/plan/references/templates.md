# Plan Skill — File Templates

Templates for files the `plan` skill writes (full mode and `--quick`). Substitute the
bracketed fields. `STORIES_INDEX.md` and `FEATURE_INDEX.md` are **not** here — they are
generated by `scripts/ck-index.sh` from story frontmatter (see
[`data-model.md`](../../../references/data-model.md)); never hand-write them.

---

## Project Overview Template

Used for `PROJECT_OVERVIEW.md` (New / Full Project Mode) at the root of the dated folder.

```markdown
# Project Overview: [Project Name]

## Vision

[One paragraph: the project vision and the problem it solves]

## Architecture

[ASCII/text architecture diagram, derived from the spec]

## Tech Stack

| Layer | Technology | Version |
| ----- | ---------- | ------- |
| ...   | ...        | ...     |

## Components

### [Component 1 Name]

- **Purpose:** [what it does]
- **Technology:** [stack]
- **Key responsibilities:** [list]

## Key Design Decisions

- [Decision]: [rationale]

## Non-Functional Requirements

- **Performance:** [targets]
- **Security:** [considerations]
- **Compatibility:** [platforms/OS]

## References

- Specification: [path to original spec file]
- Generated: [date]
```

## Feature Overview Template

Used for `FEATURE_OVERVIEW.md` (Feature Mode — Add Feature). Replaces `PROJECT_OVERVIEW.md`
and includes: feature description and motivation; existing components affected; new
components introduced; integration points with the existing system.

---

## Epic Template

Used for `epics/NN_<epic-slug>/EPIC.md`. Carries **frontmatter** and has **no
`## Stories` table** — the story list is generated into `STORIES_INDEX.md`. The generator
reads `description` for the `FEATURE_INDEX.md` cell, and links the `Docs` cell when the
epic `slug` matches a `docs/architecture/features/<slug>/index.md`. **Set `slug:` to the
owning feature-doc dir name whenever one exists** (several epics may share one feature —
e.g. epics `03_keyboard-split-engine` and `04_keyboard-split-desktop` both get
`slug: keyboard-split`); an unlinked `Docs` cell strands builders without their
architecture doc. `title`/`description` must not contain `|` (table cells).
Leave `integration:` empty — `build` fills it on the first story of the epic
([`branch-topology.md`](../../../references/branch-topology.md)).

```markdown
---
epic: NN
slug: [epic-slug]
title: [Epic Title]
description: [one-line goal — becomes the FEATURE_INDEX Description cell]
integration:
---

# Epic [NN]: [Epic Title]

## Description

[2-3 paragraphs: the epic scope, what it delivers, and why it matters]

## Goals

- [Goal 1]
- [Goal 2]

## Scope

### In Scope

- [Item]

### Out of Scope

- [Item]

## Dependencies

- **Depends on:** [prerequisite epics/stories, or "None"]
- **Blocks:** [epics/stories that depend on this]

## Acceptance Criteria

- [ ] [Criterion 1]
- [ ] [Criterion 2]

## Technical Notes

[Architectural decisions, patterns, or constraints specific to this epic]
```

## Story Template

Used for `epics/NN_<epic-slug>/stories/SS_<story-slug>.md` in **both** full and `--quick`
mode. The **frontmatter is the source of truth** for status, size, dependencies, and
touched files (see [`data-model.md`](../../../references/data-model.md)). Keep it
generator-readable: one `key: value` per line, inline `[…]` list values (or `[]`), no
block/multiline scalars. `status` lowercase, `size` uppercase `S`/`M`.

```markdown
---
id: [EE]-[SS]
title: [Story Title]
epic: [EE]
status: todo
size: [S|M]
blocked_by: [id, ...]
files: [path, ...]
issue:
prior_status:
---

# Story [EE]-[SS]: [Story Title]

## Description

[Clear description of what this story implements and why]

## Acceptance Criteria

- [ ] [Criterion 1 — specific, testable]
- [ ] [Criterion 2]
- [ ] [Criterion N]

## Implementation Tasks

Ordered, concrete, verifiable steps one `build` session follows — specific to this story,
not generic TDD phases.

1. [ ] [Concrete step]
2. [ ] [Next step — continue until every acceptance criterion is satisfied]

## Technical Notes

[Implementation guidance, patterns to follow, algorithms, API contracts, data structures]
```

**Frontmatter notes:**

- `blocked_by` / `files` — inline flow `[a, b]` or empty `[]`. `files` lists the paths the
  story creates or modifies (the conflict-detection key); `[]` when unknown (`build` fills it).
- `issue:` / `prior_status:` — left empty by `plan`; `ship` writes `issue`, `fix`/`build` manage `prior_status`.
- `title` — no `Story EE-SS:` prefix (that lives in the body heading only).
