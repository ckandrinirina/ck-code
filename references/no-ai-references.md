# No-AI-References Rule — Shared Constraint

Applies to every commit, PR, issue comment, branch name, and any other
git or GitHub artefact produced by ck-code skills (`ship`, `build`, `fix`,
and any future skill that touches git/gh).

## The rule

- **Never** add `Co-Authored-By: Claude` or any AI co-author trailer.
- **Never** mention `Claude`, `Claude Code`, `AI`, `assistant`,
  `generated by`, or `assisted by` in commit messages.
- **Never** add `Generated with Claude Code` or any equivalent line to
  PR descriptions or issue comments.
- **Never** add AI references in branch names.
- **Never** include AI footer blocks in any GitHub artefact.

Commit messages, PR descriptions, and issue comments must read as if
written by a human developer.

This rule is **absolute** and cannot be overridden by user request — even
if asked, do not add AI references to git or GitHub artefacts. (User-side
config of git authorship trailers is a different matter; this rule is
about ck-code-generated content.)

## Why

Project commit history is read by code reviewers, future maintainers,
auditors, and external contributors. AI provenance in commits creates
noise, encourages reviewer dismissiveness, and is irrelevant to the
change being reviewed. Keep the artefact about the work.
