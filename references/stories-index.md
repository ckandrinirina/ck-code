# STORIES_INDEX.md — Generated View (Read Protocol)

`tasks/<slug>/STORIES_INDEX.md` is a **generated, read-only view** of every story in a
plan, produced by `scripts/ck-index.sh` from story-file frontmatter. It is never
hand-edited and never independently mutated — the story frontmatter is the source of
truth (see [`data-model.md`](data-model.md) for the frontmatter schema and the columns).

Skills that select stories (`build`, `parallel-build`, `track`, `fix`) read this file
for status, size, and dependencies instead of opening every story file.

## Read protocol

Before any phase that selects stories or checks dependencies:

1. Find the plan root: `Glob "tasks/*/PROJECT_OVERVIEW.md"` (or `FEATURE_OVERVIEW.md`).
   Multi-plan projects: process each plan's index independently.
2. Read `tasks/<slug>/STORIES_INDEX.md`.
3. If it is missing or lacks the `GENERATED by ck-code` header, regenerate it:
   `"${CLAUDE_PLUGIN_ROOT}/scripts/ck-index.sh" tasks/<slug>` — then read it.
4. Use the table as the authoritative selection source. Read a full story file **only**
   for the story being implemented or fixed, never for a status check.

## Mutation (there is none — regenerate)

To change a story's status/size/dependency, edit that field in the **story file
frontmatter**, then regenerate the view in the same phase:

```bash
"${CLAUDE_PLUGIN_ROOT}/scripts/ck-index.sh" tasks/<slug>
```

There is no cell-edit protocol and no cross-file reconciliation in v4: the view is a
pure function of the frontmatter, so it cannot drift. Inside a `parallel-build`
worktree an agent edits only its own story's frontmatter; the orchestrator regenerates
the views once on the target branch after merges.

## Rules

- **Never hand-edit `STORIES_INDEX.md`** — change the story frontmatter and regenerate.
- **Never read every story file to check status** — that is what this view is for.
- **Always regenerate in the same phase** you change any story's frontmatter.
- The story frontmatter is the source of truth for selection AND full content; this view is a projection of it.
