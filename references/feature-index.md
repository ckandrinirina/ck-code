# FEATURE_INDEX.md — Generated View (Read Protocol + Selection Gate)

`tasks/FEATURE_INDEX.md` is a **generated, read-only view**: one row per epic across all
plans, rolled up from story-file frontmatter by `scripts/ck-index.sh`. It sits above the
per-plan `STORIES_INDEX.md` — skills read it FIRST to see which features exist and which
are unfinished, pick one, and only THEN drill into that feature's stories. It is never
hand-edited (see [`data-model.md`](data-model.md) for the schema and the rollup rule).

See also: [`stories-index.md`](stories-index.md) — the per-plan story view this sits above.

## Definition: feature = epic

Each `epics/NN_<slug>/` in any plan is exactly one row, and `NN` is unique across every
plan ([`data-model.md`](data-model.md#epic-and-story-numbers-are-globally-unique)) — so
the `Feature` cell identifies its epic on its own and the `Plan` cell is informational,
never needed to disambiguate. `Status` and `Stories` are
**computed** from that epic's story statuses (never stored): `MERGED` when every non-`skip`
story is `done` **and** `delivery: merged`; `DONE` when every non-`skip` story is `done`
but at least one has not reached the trunk; `IN PROGRESS` when any story is
`in-progress`/`bug` or some-but-not-all are `done`; `TODO` when none has started. A `bug`
story counts as not-done. The `Docs` cell routes to
`docs/architecture/features/<slug>/index.md` (or `—` if absent).

**`MERGED` and `DONE` are both finished.** `MERGED` is strictly stronger — it adds "and it
is all on the trunk branch". Nothing that looks for remaining work may treat a `MERGED` row
as unfinished; see the read protocol below.

**"Feature" here is the index sense — one row per epic.** The delivery branch
`feat/<plan-slug>` in [`branch-topology.md`](branch-topology.md) is the *plan* sense: one
branch collecting several epics. The two never refer to the same thing.

## Read protocol

Before any phase that selects work (`build` Phase 1 / PARALLEL MODE P1):

1. Read `tasks/FEATURE_INDEX.md`. If missing or lacking the `GENERATED by ck-code`
   header, regenerate: `ck-index` — then read it.
2. Parse the table as the authoritative feature list. Do NOT open any `STORIES_INDEX.md` yet.
3. Compute the **unfinished set** = rows whose `Status` is neither `DONE` **nor** `MERGED`.
   Both are finished states; counting `MERGED` as unfinished would re-offer completed,
   already-shipped features for building.
4. Apply the **feature-selection gate** (below).
5. Only after a feature is chosen, read its `Plan` → `STORIES_INDEX.md`, filtered to that
   epic's `NN`, for story selection / parallel-safe / wave logic scoped to that feature.

## Feature-selection gate (build — inline and PARALLEL MODE)

Branch on the size of the unfinished set:

- **0 unfinished** → tell the user every feature is finished (`DONE` or `MERGED`); suggest
  `/ck-code:plan` to add a feature. Stop.
- **1 unfinished** → auto-select it (announce which); proceed to its story selection.
- **2 unfinished** → skip the feature prompt; fall through to the existing story-selection
  flow across both. The threshold for asking is **strictly more than two**.
- **> 2 unfinished (3+)** → **AskUserQuestion: "Which feature do you want to build?"** —
  list each unfinished feature as `NN · Name (Plan) — Status, done/total — Description`.
  Single-select; the choice scopes the run to that epic. A story-ID / `--epic` argument
  bypasses this gate — explicit scope is always respected, and a globally unique number
  resolves its own plan with nothing to ask.

## Mutation (there is none — regenerate)

Feature status/counts are computed by the generator from story frontmatter. To change
them, change a story's `status` and run `ck-index`. The `Docs` cell is filled by the
generator when `features/<slug>/index.md` exists. There is no cell-edit protocol and no
"recompute the rollup in-phase" obligation — the rollup is always fresh because it is
regenerated, never stored.

## Rules

- **Never hand-edit `FEATURE_INDEX.md`** — change story frontmatter (and/or add the
  feature doc) and regenerate.
- **Never open a per-plan `STORIES_INDEX.md` before reading `FEATURE_INDEX.md`** in selection.
- **Never treat `MERGED` as unfinished** — it is `DONE` plus "all of it is on the trunk branch".
- **Always ask which feature to build when more than two are unfinished**; with 0/1/2, never prompt.
- **Always regenerate after changing any story's frontmatter** so the rollup stays current.
